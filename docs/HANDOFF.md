## 手順

### 1. [ ] 最新を取って `main` に取り込む

```
git fetch origin
git checkout main
git pull origin main
git merge --ff-only origin/claude/compassionate-hawking-excwxw
git push origin main
```

`--ff-only` が失敗したら（`main` に別の変更が入っていたら）、止めて社長に確認する。

### 2. [ ] 依存を入れて、テストが通ることを確かめる

```
npm ci
npm run check
cd server && npm ci && npx tsc --noEmit && cd ..
```

351件が通ればよい。落ちたら、ここで止めて原因を調べる。

### 3. [ ] TypeSafe の鍵を Worker に入れる（本番）

```
cd server
npx wrangler secret put TYPESAFE_API_KEY
```

聞かれたら、TypeSafe の管理画面の API キーを貼る。**チャットやファイルには貼らない。**
いまの本番のコードはこの鍵を使わないので、入れた時点では何も変わらない。

### 4. [ ] サーバーを公開する（本番）

```
cd server
npx wrangler deploy
```

- DB（D1）の変更は無いので、migration は要らない
- 出てきた **Version ID を控える**（手順7で記録する）
- 公開後、`npx wrangler tail` を開いておくと、相談ごとに `maya_turn` の行が出る。
  `"router":"off"`、`"route":"legacy"` になっていれば、OFF のまま従来どおり動いている

### 5. [ ] アプリを配信する（EAS Update）

```
npm run update:ios
```

- 端末のDBに列を1つ足している（migration 5：回答ごとの経路を保存する `route_json`）。
  アプリの起動時に自動で適用される。ネイティブの変更は無いので、ビルドは不要
- 出てきた **Update group ID を控える**

### 6. [ ] 実機で確かめる

1. アプリを開き直して更新を受け取る
2. 設定画面に「Jev による道具の判定」が出ること。
   「TypeSafe のキーがありません」と**出ない**こと（出たら手順3がまだ）
3. **OFF のまま**1回相談し、回答の下の「経路」が「従来」になっていること
4. ON にして、次の質問を順に試す。回答の下の「経路」を開いて見る

| 質問 | 期待する経路 |
|---|---|
| 今日の体重と食事どうだった？ | 先読み（fitlog_day）、1往復 |
| 今月Amazonでいくら売れた？ | 先読み（haksai_sales）、1往復 |
| 粗利率って何？ | データ不要、道具なし、1往復 |
| 減量中のタンパク質の目安は？ | 固定ルール（fitlog_day）。自分の体重で答える |
| 前に値上げについて何て決めたっけ？ | 候補を絞って Gemini |
| おはよう | データ不要 |

5. おかしければ、**設定画面で OFF に戻せばすぐ元どおり**（公開し直しは不要）

## 使いながら見ること（急がない）

評価で見つかった点。実際の相談で起きるか、経路の表示で確かめる。

- 固定ルールが「PFCって何？」のような言葉の意味の質問にも効き、FIT LOG を読む
  （体の話かを言葉で判定しているため）。気になるなら、ルールの条件を狭める
- 会話の中にもう答えがある質問（「この数字どう思う？」など）でも、データを取り直す
- Jev が迷ったときは、応答時間のばらつきが大きい（1回 11.5秒の例あり）
- 固定ルールを足したくなったら `server/src/jevRules.ts`。設定画面の一覧にも出る
