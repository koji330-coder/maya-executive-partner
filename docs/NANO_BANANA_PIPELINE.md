## 1. 構成

Google Gemini の画像モデルを叩く Node CLI。`@google/genai` 2.21.0 と sharp。

| コマンド | 用途 |
| --- | --- |
| `npm.cmd run doctor` | 診断。APIを呼ばないので課金なし |
| `npm.cmd run generate` | プロンプトから新規生成 |
| `npm.cmd run edit` | 参照画像を渡して編集。差分素材はこれで作る |
| `npm.cmd run batch` | マニフェストで順次実行。並列にしない |
| `npm.cmd run inspect` | 出力画像の実形式・寸法を検査 |

モデルは4段階。`lite` が差分の量産、`flash` が既定、`pro` が最終マスター。
実績プロジェクトでは差分を `gemini-3.1-flash-lite-image` で回している。

安全設計として、`--dry-run` はAPIを呼ばず、既存ファイルは `--force` なしでは
上書きしない。相対パスは常に `nano-banana/` 基準。

## 2. 差分素材の作り方

**幾何的に加工するのではなく、モデルに描かせる。**

採用済みの表情画像を「固定された親」として渡し、1箇所だけ変える指示を出す。
プロンプトは親画像の何を保持するかを具体的に列挙する。実績プロジェクトの
まばたき用プロンプトは、髪の毛一本、眼鏡のブリッジ、手の本数まで名指しで
固定したうえで「両目だけを自然な瞬きに変える」と指示している。

出力は**純白背景**で作り、あとから `rembg` の `isnet-anime` モデルで背景を抜く。

## 3. 合成方式

ここが要。位置合わせは画像全体の一致ではなく、**楕円マスクによる部分上書き**で
成立させている。

- 口パク: `closed_base_with_masked_open_mouth_overlay`
- まばたき: `closed_base_with_two_masked_eye_overlays`

口を閉じた画像を土台として出したまま、口を開けるときは開いた画像を口の楕円だけ
くり抜いて重ねる。まばたきは目の楕円を2つ使う。マスクの外でモデルが揺らいでも
画面には出ない。

マスクはキャンバスに対する百分率で持つ。

```json
{"centerX": 50, "centerY": 61, "radiusX": 8, "radiusY": 5.8}
```

## 4. 運用で分かっていること

実績プロジェクトの `lipsync-mask-review.md` に実測付きで記録されている。
同じ失敗を繰り返さないために転記する。

**マスクは実測する。決め打ちは必ずずれる。**
closed画像とopen画像のピクセル差分を取り、変化した領域の重心と広がりから
楕円を決める。実績プロジェクトでは決め打ちの値が数%ずれており、「OPENを
選んでも口が閉じたままに見える」という形で表面化した。

**半径は実測の広がりより大きく取る。**
同じ大きさだと、マスクの外に閉じた口の輪郭がはみ出して貼り付けたように見える。

**マスクは状態ごとに持つ。**
キャラクター単位の共通定数にすると必ず破綻する。実績プロジェクトでは先生と
生徒で1つのマスクを共有していて生徒だけずれていた。ポーズが変わると口の位置も
変わるため、最終的に状態ごとの値を持つ形になっている。

## 5. MAYAの仕様との差分

実績パイプラインが持つ状態数は、MAYAの現仕様より少ない。

| 項目 | MAYAの現仕様 | 実績パイプライン |
| --- | --- | --- |
| 口の状態 | closed / small / open | closed / open |
| 目の状態 | open / half / closed | open / blink |
| 合成 | レイヤー差し替え | 楕円マスクで部分上書き |
| 生成背景 | 中間グレー | 純白 → rembg/isnet-anime |

v0.1は実績側に合わせる。`MouthState` と `EyeState` の型は3値のまま残し、
アセット解決側で `small` と `half` を最寄りの素材へ倒す。`LipSyncController` は
しきい値を揃えれば2値で動く。中間素材は、必要だと分かった時点で1枚足せばよい。

背景色は要判断。MAYAの採用済みマスターは中間グレーで生成しており、単純な
キーイングで抜けることを実測済み。実績パイプラインは純白と `isnet-anime` の
組み合わせ。`isnet-anime` はアニメ調向けのモデルなので、2.5D寄りのMAYAで
同じ品質が出るかは未検証。

## 6. MAYAでの実証結果（2026-09-11）

**この画風でも通用する。**採用済みマスターから、まばたきと口を開いた状態を
`lite` で1枚ずつ生成し、実測マスクで合成した。

- API 403 は解消済み。`edit` が2回とも通った
- 生成物: `assets/reference/pipeline-test/`。4状態（マスター／まばたき／
  口を開く／同時）の合成結果と `masks.json`

### 構図はずれなかった

懸念していた位置ずれは起きなかった。両画像を同じ寸法に揃えて最適な平行移動を
探索したところ、最良は dx=0 dy=0 で、移動なしと残差が同じだった。差分の
ヒートマップも**両目だけ**が光り、それ以外は髪や襟の輪郭に出る微差だけだった。

口を開いた版では口が動いたのに加えて笑みがわずかに変わっていたが、マスクの
外なので画面には出ない。マスク合成の狙いどおり。

### 実測したマスク（キャンバス比）

| 部位 | 重心 | 実測の広がり | 採用半径（1.5倍） |
| --- | --- | --- | --- |
| 左目（向かって左） | 38.9%, 29.1% | 4.6%, 2.3% | 7.0%, 3.6% |
| 右目（向かって右） | 58.2%, 27.1% | 5.2%, 2.5% | 7.6%, 3.9% |
| 口 | 51.6%, 39.8% | 9.7%, 2.3% | 14.5%, 3.5% |

口の重心が 39.8% なのは、MAYAのマスターが胸上の構図で顔が上寄りにあるため。
実績プロジェクトの 61〜68% とは前提が違う。**マスクは流用できない**という
運用記録の指摘がそのまま当てはまった。

### 本番で変えること

`lite` の 1K / 3:4 出力は 896x1200 で、マスターの 1086x1448 より小さい。
本番は `flash` か `pro` を 2K で回し、マスター以上の解像度で出す。
