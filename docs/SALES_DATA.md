# 売上データ

**MAYAは売上を Cloudflare D1 から読みます。**スプレッドシートやGASを直接は
叩きません。

## 構成

```
スプレッドシート（正）
  → GAS（計算）
  → D1（計算結果の写し）  ← MAYA はここだけを読む
```

GASは応答に数十秒かかります。相談中にそれを待たせることはできないので、計算
結果を D1 に同期し、読み出しは D1 から行います。同期と D1 は別プロジェクト
「売上ラボ」の管轄で、MAYA 側は読むだけです。

## 読み出し口

売上ラボの Pages Functions にある読み取り専用のAPIを使います。

```
GET /api-lab/sales?action=getAvailablePeriods
GET /api-lab/sales?action=getPeriodSummary&periodKey=YYYY-MM
```

月の一覧と、月ごとのサマリー、商品別、経費、日別が返ります。**MAYA 側に D1 の
バインディングも Worker も要りません。**D1 に何が入っていても、受け取り側は
この2本から変わりません。

## 接続する前に決めること

### 認証

いまの関数は呼び出し元を確かめていません。`ALLOWED_ORIGINS` はブラウザだけが
従う仕組みで、**スマホアプリからの呼び出しには効きません。**公開URLになった
時点で、URLを知っていれば誰でも売上が取れます。

Cloudflare Access のサービストークンか、共有秘密の確認を関数側に入れてから
公開します。アプリ側の資格は `expo-secure-store` に置きます。

### 同期の途中で月が消えないか

同期はその月を DELETE してから INSERT し直しています。1つのトランザクション
で実行されないと、同期中に読んだときに「その月が無い」「商品が0件」が返ります。
`wrangler d1 execute --file` がリモートで原子的に動くかは未確認です。

自動化するなら Cron Trigger の Worker から `env.DB.batch([...])` で書くのが
確実です。batch は1トランザクションで走り、API トークンが Cloudflare の外に
出ません。

### 無料枠のキーに実データを渡さない

MAYA に数字を読ませると、実際の売上が Gemini に送られます。無料枠は送信内容が
改善に使われる場合があります（`docs/LLM_INTEGRATION.md`「無料枠と機密情報」）。
**実データを読ませるなら有料キーに切り替えます。**表示だけなら LLM には
渡りません。

## MAYA に渡すときの約束

**`imported_at` を必ず一緒に渡します。**

「8月の粗利率は24%です」と「昨日14時時点の8月の粗利率は24%です」は、判断の
材料として別物です。同期が止まっていても、MAYA が古い数字を今の数字として
断言しないようにします。`docs/PRODUCT_REQUIREMENTS.md` §6 の「事実と推測を
分ける」がここに当たります。
